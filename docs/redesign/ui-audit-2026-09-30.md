# UI audit, 2026-09-30 (Gate R input, nothing changed yet)

Jay's ask: every button, card, doodle and custom component adapts to phone,
tablet and desktop with its own layout, sizes and alignment; every
interactive component has every state (idle, hover, press and hold, focus,
disabled, loading, success, error, cancel); one production-grade, reused
system. Navbar is out of scope (Jay: "the whole navbar is perfect").

Method: the running site (local demo, backend on), measured with computed
styles at 375, 768 and 1440 px, plus a CSS and markup sweep. Numbers below
are measured, not estimated.

## 1. Responsive foundation
- 36 distinct width breakpoints across the CSS, no shared set. Top ones:
  768 (min and max, 34 uses), 640, 1024, 480, 860, 861, 600.
- `max-width: 768px` and `min-width: 768px` both match at exactly 768 px,
  so tablets in portrait get both rule sets at once.
- No page overflows sideways at 375, 768 or 1440 (checked 16 routes). The
  commit heatmap and one code block run past the edge inside their own
  scroll areas, which is intended.
- Proposal (mechanical, agent's call): four named tiers used everywhere,
  phone < 600, tablet 600 to 1023, laptop 1024 to 1439, wide 1440 and up,
  each page and component designing its own layout per tier.

## 4. Pages Jay named
Projects
- Filter row (All, Client Work, Personal, AI/ML, Open Source) uses grey
  inset clay pills found nowhere else; does not match the blue Talk Chip or
  the navbar pill.
- Cards: two tag styles inside one card, status line and role line float
  with large uneven gaps, a stray dash before the role, unequal heights,
  "Read the case study" arrow is a text glyph and fades under the bottom
  blur band, cover area is a placeholder label.

About
- All six section headings carry the underline doodle with a width (180)
  but no height, so the browser draws it in its default 150 px tall box.
  That is the gap between "What I build" and the role cards, repeated six
  times down the page. Root cause, not taste: fix is a height on
  `.section-head .doodle`.

Resume
- Outbound arrows are a text character added by a global rule
  (`css/base/typography.css`, every outside link site-wide), not a drawn
  icon; they depend on the font and read faint.
- 25 more arrows are typed into page text ("Read the case study" etc.).
- GitHub and LinkedIn drawn icons exist in `assets/icons/` but are unused
  in the contact row; there is no drawn arrow icon at all.
- Contact links are 21 px tall.

## 5. Fixed during this audit
- `/book`: the email fallback box and the name form ignored `hidden`
  (their own `display: grid` beat it), so the fallback stayed on screen
  under a live picker. One rule in `css/pages/slash.css`. Rebuilt and
  tested on the build box: 131/131.
